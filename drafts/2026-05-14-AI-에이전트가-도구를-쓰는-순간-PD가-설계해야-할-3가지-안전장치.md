# AI 에이전트가 도구를 쓰는 순간, PD가 설계해야 할 3가지 안전장치

> AI 에이전트 생태계 심화: 도구 사용(Tool Use)과 자율성 — Product Designer 관점

## 들어가며

요즘 "AI 에이전트"라는 단어가 너무 자주 들립니다. 작년까지는 챗봇이었던 인터페이스가, 올해는 직접 검색하고, 파일을 열고, API를 호출하고, 심지어 결제까지 하기 시작했습니다.

기획자나 개발자만의 영역으로 보일 수 있지만, **Product Designer에게 더 중요한 변화**입니다. 사용자가 "Send"를 누르는 순간 끝나는 흐름이 아니라, 그 후로 에이전트가 **몇 분~몇 시간 동안 도구를 들고 일하는 흐름**을 우리가 설계해야 하기 때문입니다.

이 글에서는 에이전트가 도구를 사용하는 순간에 PD가 반드시 설계해야 할 **3가지 안전장치**를 정리합니다.

---

## 1. 도구 사용 가시화 (Tool Use Visibility)

가장 흔한 실수는 "AI가 알아서 잘 처리합니다 ✨" 같은 모달을 띄우고 끝내버리는 것입니다.

사용자 관점에서는 그 순간이 **블랙박스**가 됩니다. 5초가 지나도, 30초가 지나도 같은 스피너만 돌아갑니다. 사용자는 곧 의심합니다 — "지금 뭐 하고 있는 거지?"

### 설계 원칙

- **현재 사용 중인 도구를 라벨로 노출**: `🔍 웹 검색 중 → "토스증권 차트 UI 분석"` 같이 도구 + 파라미터를 함께
- **단계별 상태 카드**: GitHub Copilot Workspace나 Cursor의 Agent 모드에서 보듯, 단계를 카드로 시각화
- **실시간 결과 미리보기**: 검색 결과 첫 3개를 즉시 보여주고, 사용 여부를 사용자가 가볍게 확인

### 사례
Cursor, Claude Code의 "Read tool", "Bash tool" 표시는 단순한 로그가 아니라 **신뢰의 인터페이스**입니다. 에이전트가 무엇을, 왜 사용했는지를 보여줘야 사용자는 그 다음 단계를 위임할 마음이 생깁니다.

---

## 2. 권한 게이트 (Permission Gate)

에이전트가 **읽기**만 한다면 사용자는 거의 신경 쓰지 않습니다. 문제는 **쓰기·전송·결제** 같은 비가역적 행동을 할 때입니다.

### 게이트 3단 분류

| 단계 | 행동 유형 | UX 설계 |
|------|----------|---------|
| 🟢 1단계 | 읽기 (검색, 조회) | 자동 실행, 결과만 노출 |
| 🟡 2단계 | 쓰기 (파일 생성/수정, 코멘트 작성) | 결과 미리보기 + 한 번에 적용 |
| 🔴 3단계 | 비가역 (전송, 결제, 외부 게시) | **명시적 확인 모달 필수** |

여기서 **포스텔의 법칙(Postel's law)**을 떠올립시다 — "보내는 것에는 보수적으로, 받는 것에는 관대하게". 에이전트의 외부 송신은 사용자의 송금만큼이나 보수적으로 다뤄야 합니다.

### 사례
ChatGPT의 Operator, Anthropic의 Claude Computer Use 모두 결제·발송 단계에서 명시적 사용자 확인을 강제합니다. 이 패턴이 사실상 업계 표준이 되어가고 있습니다.

---

## 3. 되돌리기와 멈춤 버튼 (Undo & Kill Switch)

에이전트가 자율적으로 일할수록, **사용자가 통제권을 회수할 수 있는 명확한 출구**가 필요합니다.

### 설계 체크리스트

- [ ] 작업 진행 중 언제든 **Stop** 버튼이 보이는가?
- [ ] 중간 결과를 **체크포인트**로 저장해 되돌릴 수 있는가?
- [ ] "Stop" 누른 뒤 작업 일부가 이미 외부에 영향을 미쳤다면, **무엇이 어디까지 진행됐는지** 명확히 보여주는가?

GitHub Copilot Workspace는 모든 변경사항이 PR 단위로 묶여 있어서, 사용자가 마음에 안 들면 **PR을 닫는 것만으로** 모든 변경을 무효화할 수 있습니다. 이게 좋은 Kill Switch 디자인입니다.

---

## 마치며

AI 에이전트 시대의 UX 디자인은 **"버튼을 디자인하는 일"에서 "위임 관계를 디자인하는 일"**로 옮겨가고 있습니다. 가시화, 권한 게이트, 되돌리기 — 이 세 가지는 사용자가 에이전트에게 안심하고 일을 맡기기 위한 최소 조건입니다.

다음 글에서는 에이전트의 **결과 검증 UX**를 다뤄보겠습니다. 에이전트가 자신 있게 잘못된 답을 내놓을 때, 사용자는 어떻게 알아챌 수 있을까요?
