# 사용자는 이미 다른 도구에 익숙하다 — B2B 분석 도구의 잭의 법칙 설계법

## 들어가며

새로운 B2B 분석 도구를 도입했을 때 "이거 왜 이렇게 동작이 안 익숙하지?"라고 느꼈던 적이 있나요? 메뉴 위치, 단축키, 필터 동작이 평소 쓰던 Google Analytics, Amplitude, Tableau와 미묘하게 어긋나면 사용자는 무의식적으로 짜증을 느낍니다. 그 짜증이 임계점을 넘으면 도입 검토는 멈춥니다.

이 현상을 한 줄로 설명해주는 UX 법칙이 있습니다. **잭의 법칙(Jakob's Law)** 입니다.

> "사용자는 자신의 시간 대부분을 **다른 사이트**에서 보낸다. 따라서 사용자는 **당신의 사이트도 그들이 이미 알고 있는 다른 사이트들과 같은 방식으로 작동하기를 원한다**."

저는 B2B 데이터 분석 서비스를 디자인하면서 이 한 문장이 신규 도구의 도입 장벽을 절반으로 줄여준다는 걸 매번 체감합니다. 오늘은 이 법칙을 B2B 분석 도구에 어떻게 적용할지, 그리고 어디에서는 의도적으로 어겨야 하는지까지 함께 살펴보겠습니다.

## 본문

### 1. 왜 B2B 분석 도구일수록 잭의 법칙이 강력한가

B2C 서비스 사용자는 한 앱에 몇 분 머무릅니다. B2B 분석 도구 사용자는 하루 4~6시간을 도구 안에서 보냅니다. 두 가지 뜻이 겹칩니다.

1. 평생 학습된 다른 도구의 멘탈 모델이 깊게 새겨져 있습니다. (대체로 Excel, GA4, Tableau, Mixpanel, Notion)
2. 그 멘탈 모델과 충돌하는 패턴은 매번 작업 흐름을 끊습니다. 한 번 흘려보낼 마찰이 아니라 하루에 수십 번 누적되는 비용입니다.

B2B 분석 도구에서 잭의 법칙을 어기는 비용은 B2C보다 10배 이상 큽니다. 도입 결정자가 "사용자 학습 비용"을 가장 크게 우려하는 이유도 여기에 있습니다.

### 2. 어디에서 잭의 법칙을 따라야 하는가 — "지루해도 따르라" 영역

다음 세 영역은 거의 무조건 업계 표준을 따르는 편이 안전합니다.

**① 데이터 조회의 기본 동작**
- 표 정렬: 컬럼 헤더 클릭 한 번에 오름차순, 두 번에 내림차순
- 다중 정렬: Shift + 클릭
- 필터 위치: 상단 또는 좌측 사이드, 적용 후 칩(chip) 형태로 노출
- 날짜 범위 선택기: 최근 7/30/90일 프리셋 + 사용자 지정 캘린더

GA4, Mixpanel, Amplitude, Looker가 거의 동일하게 쓰는 패턴입니다. 다르게 만들면 손해만 남습니다.

**② 차트 인터랙션 컨벤션**
- 마우스 호버 시 툴팁
- 범례 클릭으로 시리즈 토글
- 더블클릭 또는 박스 셀렉트로 줌
- 우상단의 다운로드/확대 아이콘

금융 차트 영역(증권 앱 등)에서는 색상 컨벤션까지 강하게 학습되어 있습니다. 한국은 매수=빨강·매도=파랑, 미국은 매수=초록·매도=빨강. 사용자의 국가 시장 컨벤션을 거스르면 즉각 혼동이 생깁니다.

**③ 키보드 단축키**
- 검색: `/` 또는 `Cmd/Ctrl + K`
- 닫기: `Esc`
- 새로 만들기: `Cmd/Ctrl + N`
- 저장: `Cmd/Ctrl + S`

Linear, Notion, Figma가 정착시킨 패턴으로 이제 B2B SaaS의 사실상 표준입니다. 자기만의 단축키 체계를 만들면 파워유저가 가장 먼저 떠납니다.

### 3. 어디에서 의도적으로 어겨야 하는가 — "차별화 무기" 영역

잭의 법칙을 무조건 따르라는 뜻은 아닙니다. 따르지 않을 때 더 큰 가치를 만드는 영역이 분명히 있습니다.

**① 도구의 핵심 차별 가치를 드러내는 메인 워크플로우**
새 서비스를 만든 이유는 결국 "기존 도구로 안 되는 무언가"를 해결하려는 것입니다. 그 부분은 새로운 멘탈 모델을 가르치더라도 밀고 나가야 합니다. Mixpanel이 처음 등장했을 때 "Funnel" 빌더는 SQL 기반 분석가에게 낯선 인터랙션이었지만 핵심 가치였기에 정착되었습니다.

**② 정보 위계가 다른 새 데이터 구조**
기존 도구가 "이벤트 단위" 분석이라면 새 도구는 "여정 단위" 분석일 수 있습니다. 이 경우 표 형태에 억지로 우겨넣지 말고 여정에 맞는 시각화를 새로 만들어야 합니다. 다만 그 새 시각화 내부의 조작 방식(호버·줌·다운로드)은 앞서 말한 컨벤션을 그대로 유지해야 합니다.

**③ AI 어시스턴트의 대화형 인터랙션**
ChatGPT 등장 이후 새 컨벤션이 형성 중인 영역입니다. 잭의 법칙은 이제부터 만들어지는 새 표준의 한 축이 되는 것 자체에 의미가 있습니다. 단, 입력창의 동작 패턴(엔터로 전송, Shift+엔터로 줄바꿈, `/`로 명령 팔레트 열기)은 이미 컨벤션이 굳었으므로 따라야 합니다.

### 4. 잭의 법칙을 적용하는 4단계 체크리스트

새 화면을 설계할 때 저는 다음 순서로 점검합니다.

1. **벤치마크 매핑** — 같은 기능을 제공하는 메이저 도구 3~5개를 나란히 띄워두고 각 인터랙션을 정리합니다. (정렬, 필터, 차트 조작, 단축키)
2. **컨벤션 채택 결정** — 3개 이상이 동일 패턴이면 "표준"으로 간주하고 그대로 채택합니다.
3. **차별화 결정** — 우리 도구의 고유 가치를 위해 새 패턴이 필요한가? 그렇다면 그 화면 안에서만 일관성을 깨고 나머지는 표준을 유지합니다.
4. **전환 비용 보조 장치** — 새 패턴을 도입한 화면에는 첫 진입 시 인터랙션 힌트(coach mark), 이전 도구와의 매핑 가이드, undo 동선을 반드시 제공합니다.

### 5. 실전 사례 — B2B 분석 도구의 "데이터 탐색" 화면

저희 팀이 데이터 탐색 화면을 다시 설계할 때 적용한 사례를 공유합니다.

- **유지한 표준 (잭의 법칙 준수)**
    - 좌측 사이드의 필터 패널 (Tableau·Looker 패턴)
    - 컬럼 헤더 클릭 정렬, Shift+클릭 다중 정렬
    - `Cmd/Ctrl + K`로 모든 데이터셋 검색
    - 우상단 다운로드 아이콘
- **의도적으로 어긴 영역 (차별화 무기)**
    - 메인 패널 중앙에 "AI 분석 어시스턴트" 입력창을 항상 표시 (기존 도구는 별도 메뉴)
    - 차트와 표를 동시 듀얼 뷰로 좌우 분할 (기존 도구는 탭 전환)
- **전환 비용 보조**
    - 듀얼 뷰는 한 번에 한쪽만 사용하던 사용자를 위해 "한쪽 접기" 토글을 좌상단 고정
    - AI 입력창은 첫 진입 시 인터랙티브 투어 1회 노출, 이후 비활성

결과는? 도구 도입 시점의 평균 활성화 시간이 약 30% 줄었고 AI 어시스턴트 활용률은 전체 사용자의 70%를 넘었습니다. 표준을 따른 부분이 학습 부담을 흡수해주었기에 차별화 영역의 새 인터랙션을 학습할 여력이 사용자에게 남아 있었던 겁니다.

## 결론

잭의 법칙은 "익숙한 것을 따르라"는 보수적 조언이 아닙니다. 혁신할 영역과 따라야 할 영역을 분리하는 전략적 프레임입니다.

B2B 분석 도구의 디자이너로서 우리가 답해야 할 질문은 두 가지뿐입니다.

1. 사용자가 이미 학습한 동작을 우리가 다시 가르치려 하고 있는가? 그렇다면 멈추고 표준을 따릅니다.
2. 우리가 새로 가르쳐야 할 가치가 있는가? 그렇다면 그 영역만 의도적으로 새로 설계하고 나머지는 더 강하게 표준을 따릅니다.

표준을 따르는 건 게으름이 아닙니다. 사용자가 진짜 새로 배워야 할 가치에 집중하도록 마찰을 줄여주는 디자인 행위입니다. 새 화면을 설계할 때 잭의 법칙 체크리스트를 한 번 돌려보세요. 어쩌면 "독창적으로 다르게 만든" 사이드바 디자인이 도입 장벽의 주범일지도 모릅니다.

다음에는 같은 맥락에서 B2B 분석 도구의 "선택지 수"를 다루는 힉의 법칙(Hick's Law) 설계법을 풀어보겠습니다.
