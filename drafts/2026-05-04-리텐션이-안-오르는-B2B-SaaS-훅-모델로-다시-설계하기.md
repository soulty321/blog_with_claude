# 리텐션이 안 오르는 B2B SaaS, '훅 모델'로 다시 설계하기

> *"우리 제품은 한 번 쓰면 끝나요. 어떻게 매일 들어오게 만들죠?"*

B2B 데이터 분석 서비스를 디자인하다 보면 이 질문을 수없이 받습니다. 컨슈머 앱은 푸시 한 번에 사용자가 돌아오는데, 회사 계정으로만 들어오는 B2B 도구는 "필요할 때만" 열립니다. **DAU/MAU 비율이 0.1대를 넘기 어렵죠.**

그래서 다시 펼쳤습니다. 니르 이얄(Nir Eyal)의 *훅: 일상을 사로잡는 제품의 비밀*.

처음 읽었을 땐 "이건 인스타그램·틱톡 얘기지, B2B엔 안 통해"라고 미뤄뒀던 책입니다. 하지만 데이터 분석 서비스의 리텐션 문제를 풀면서 알게 됐습니다 — **훅 모델은 도파민 도둑질이 아니라, 가치 인식의 반복 회로를 설계하는 프레임이라는 것**을요.

이 글은 훅 모델의 4단계(Trigger → Action → Variable Reward → Investment)를 **B2B 데이터 분석 서비스 디자이너의 관점**에서 다시 해석한 기록입니다.

---

## 훅 모델 4단계 빠르게 짚기

훅(Hook)이란 사용자의 문제를 제품의 사용으로 자동 연결시키는 4단계 사이클입니다.

1. **트리거(Trigger)** — 행동을 시작하게 만드는 신호 (외부/내부)
2. **액션(Action)** — 보상을 기대하며 수행하는 가장 단순한 행위
3. **가변 보상(Variable Reward)** — 매번 약간씩 다른, 예측 불가능한 보상
4. **투자(Investment)** — 다음 사이클의 트리거가 더 강해지도록 사용자가 시간/데이터/의견을 쌓는 단계

이 4단계가 빠르게 반복될수록 사용자는 **외부 트리거 없이도 내부 트리거**(불안, 호기심, 욕구)에 의해 스스로 제품을 떠올리게 됩니다.

B2B 데이터 분석 서비스가 어려운 이유는 분명합니다 — 트리거가 약하고, 액션이 무겁고, 보상이 일정합니다. 그래서 4단계를 모두 손볼 필요가 있습니다.

---

## 1단계: 트리거 — '필요할 때만 열리는' 도구를 어떻게 깨울까

B2B에서 외부 트리거(이메일·슬랙 알림·푸시)는 양날의 검입니다. 너무 많이 보내면 알림 차단, 너무 적게 보내면 잊혀집니다. 핵심은 **사용자가 이미 신경 쓰는 정보의 변화 시점에 트리거를 쏘는 것**입니다.

실무에서 적용해본 4가지 트리거 패턴:

- **이상치 감지(Anomaly Trigger)**: "어제 대비 -28%" 같은 갑작스러운 변화만 알림. 정상 범위 데이터는 침묵.
- **목표 임박 트리거(Goal-Approach Trigger)**: 사용자가 직접 설정한 KPI에 90% 도달했을 때만 알림.
- **동료 활동 트리거(Peer Trigger)**: 같은 워크스페이스의 동료가 "주간 리포트 공유"를 했을 때 캐스케이드로 도착.
- **타이밍 트리거(Time Trigger)**: 월요일 오전 9시처럼, 행동 패턴 데이터로 추출된 *그 사용자만의* 정기 시간.

핵심은 **알림을 보낼 권리가 사용자에게서 위임된 것처럼 느끼게** 만드는 일입니다. "왜 이걸 알려주지?"가 아니라 "이걸 안 알려주면 나 큰일 났을 것"이 되어야 합니다.

내부 트리거는 어떨까요. B2B의 내부 트리거는 보통 두 가지입니다 — *불안*("내 숫자가 떨어졌을지도?")과 *책임감*("월요일 미팅 전에 자료 준비해야 해"). 디자이너는 이 두 감정을 **첫 화면에서 1초 안에** 만나도록 설계해야 합니다.

---

## 2단계: 액션 — '보고 싶다'에서 '봤다'까지 5초

훅 모델의 액션은 *보상을 얻기까지의 가장 단순한 행위*입니다. 인스타그램은 '스크롤', 트위터는 '새로고침'. B2B 데이터 분석 서비스의 액션은 보통 너무 무겁습니다.

```
대시보드 진입 → 기간 선택 → 필터 설정 → 차트 로딩 대기 → 인사이트 해석
```

이 5단계를 지나야 보상이 옵니다. **첫 보상에 도달하기 전에 사용자가 떠납니다.**

해결의 단서는 단순합니다 — *기본값(Default)*을 사용자의 마지막 행동에 맞춰 미리 채워 넣고, 첫 화면에서 **기다림 없이 어제의 핵심 변화 1줄**을 띄우는 것입니다.

> 어제 검색량 +12%, 신규 키워드 24개 발견 — 자세히 보기 →

이 한 줄이 보일 때 액션은 '클릭 한 번'이 됩니다. 5단계가 1단계로 압축되죠.

여기서 BJ 포그(Fogg)의 행동 모델이 함께 작동합니다 — *Behavior = Motivation × Ability × Trigger*. **능력(Ability)을 극단까지 끌어올리는 것이 B2B 디자이너의 첫 일**입니다.

---

## 3단계: 가변 보상 — 데이터는 매일 다르지만, '의미'는 그렇지 않다

여기가 B2B의 가장 어려운 지점입니다.

B2C 앱은 매번 새로운 사진·영상·메시지로 보상을 가변화합니다. 하지만 B2B 분석 도구는 *데이터 자체는 매일 다르지만 화면 구조는 똑같*습니다. 같은 막대그래프, 같은 KPI 카드. 사용자는 며칠만에 "별 차이 없네"라고 학습합니다.

그래서 디자이너가 만들어야 할 건 **데이터의 가변성이 아니라 '의미의 가변성'** 입니다.

- **동일한 그래프에 매번 다른 해석을 붙입니다.** "이번 주는 지난주 대비 ___ 변화가 가장 컸습니다." 빈칸이 매일 새로 채워지는 거죠.
- **임계점 돌파를 축하합니다.** "처음으로 일일 활성 키워드 1,000개를 돌파했습니다."
- **숨겨진 비교 대상을 노출합니다.** "동종 업계 평균 대비 +18%."
- **AI가 발견한 패턴을 가변 보상으로 제시합니다.** "지난 30일 중 비정상 패턴 3건 — 살펴보시겠어요?"

훅 모델이 말하는 가변 보상의 3가지 — *부족(Tribe)·사냥(Hunt)·자기(Self)* — 중 B2B 데이터 도구는 **사냥(Hunt) 보상**과 **자기(Self) 보상**을 노릴 수 있습니다. 사냥은 '인사이트를 발견했다는 짜릿함', 자기는 '내 분석 역량이 늘었다는 만족감'입니다. 둘 다 데이터의 양이 아니라 *해석의 깊이*에서 나옵니다.

---

## 4단계: 투자 — 사용자가 쌓을수록, 떠나기 어려운 제품

마지막 단계 '투자'는 B2B에서 강력한 무기입니다. 사용자가 직접 만든 자산이 많아질수록 다른 도구로 옮기는 비용은 기하급수적으로 증가합니다.

데이터 분석 서비스에서 사용자가 쌓을 수 있는 자산을 꼽아봅니다.

- **저장된 필터/세그먼트** — 자주 쓰는 검색 조건을 이름 붙여 저장
- **북마크/즐겨찾기 차트** — 매주 보는 그래프를 한 곳에
- **메모와 주석** — 특정 데이터 포인트에 "이 시기에 캠페인 진행" 같은 맥락 기록
- **공유된 워크스페이스** — 동료와 협업한 보고서, 댓글, 멘션 이력
- **알림 규칙** — 사용자가 직접 설정한 트리거 임계값

이 모든 것은 **사용자가 시간을 들여 쌓은 결과물**입니다. 그리고 다음 사이클의 트리거를 자동으로 강화합니다 — 어제 설정한 알림이 오늘의 트리거가 되고, 어제 저장한 필터가 오늘의 액션을 1클릭으로 만듭니다.

여기서 디자이너가 지켜야 할 한 가지 원칙이 있습니다 — **사용자의 '투자'를 절대 잃게 하지 말 것**. 마이그레이션, 리뉴얼, 권한 변경 같은 시스템 이벤트가 사용자의 누적 자산을 무너뜨리는 순간, 훅 사이클은 한 번에 끊어집니다.

---

## 다시, 처음 질문으로

> *"우리 제품은 한 번 쓰면 끝나요. 어떻게 매일 들어오게 만들죠?"*

훅 모델은 답합니다 — 매일 들어오게 만들지 마세요. **사용자의 문제가 발생할 때마다 가장 먼저 떠오르는 도구**가 되세요.

이건 도파민 트릭이 아니라 가치 인식 회로입니다. 트리거를 약속처럼 정확하게, 액션을 호흡처럼 짧게, 보상을 매번 약간 다르게, 투자를 사용자의 자산으로 누적시키는 것 — 이 4단계가 데이터 분석 서비스라는 무뚝뚝한 카테고리에도 그대로 작동합니다.

B2B 디자이너로서 가장 인상 깊었던 깨달음 한 줄로 글을 마칩니다.

> *"리텐션은 알림의 빈도가 아니라, 가치 인식의 빈도다."*

월요일 아침 9시. 어떤 한 줄이 사용자를 첫 클릭으로 이끄는지, 이번 주는 그 한 줄을 다시 점검해보려 합니다.
