# 자주 쓰는 기능일수록 크고 가깝게 — B2B 분석 도구의 피츠의 법칙 설계법

> "버튼을 못 찾겠어요"가 아니라 "버튼을 누르기 귀찮아요"가 진짜 문제일 때

## 1px의 마찰이 쌓이는 곳

B2B 데이터 분석 도구를 설계하다 보면 묘한 역설을 만납니다. 사용자는 분명 그 기능이 어디 있는지 압니다. 필터도, 내보내기도, 기간 선택도 다 압니다. 그런데도 잘 쓰지 않습니다.

이유는 단순합니다. **누르기까지의 비용이 너무 비싸기 때문**입니다. 화면 구석에 박힌 작은 아이콘, 두 번 세 번 펼쳐야 나오는 드롭다운, 마우스를 화면 끝까지 끌고 가야 닿는 컨트롤. 한 번이면 모르겠지만, 하루에 수백 번 데이터를 들여다보는 분석가에게는 이 마찰이 곱하기로 쌓입니다.

이 비용을 정량적으로 설명해 주는 것이 바로 **피츠의 법칙(Fitts's Law)** 입니다.

## 피츠의 법칙이란 무엇인가

1954년 심리학자 폴 피츠(Paul Fitts)는 하나의 공식을 제안했습니다. 어떤 대상을 가리키는 데 걸리는 시간은 **대상까지의 거리(D)** 와 **대상의 크기(W)** 로 결정된다는 것입니다.

쉽게 말하면 이렇습니다.

- 멀수록 느립니다 — 마우스(혹은 손가락)가 이동할 거리가 길수록 시간이 더 걸립니다.
- 작을수록 느립니다 — 목표가 작을수록 정확히 조준하느라 시간이 더 걸립니다.

그래서 결론은 명료합니다. 자주, 빠르게 눌러야 하는 대상은 크게 만들고, 사용자 가까이에 둬야 합니다. 반대로 실수하면 위험한 대상(삭제, 영구 변경)은 일부러 작게, 멀리 두어 마찰을 더해야 합니다.

## B2B 분석 도구에서 피츠의 법칙이 깨지는 순간들

소비자 앱과 달리 B2B 분석 도구는 화면 밀도가 극도로 높습니다. 표, 차트, 필터, 범례가 한 화면에 빽빽이 들어찹니다. 이 환경에서 피츠의 법칙은 더 자주, 더 아프게 위반됩니다.

### 1. 가장 자주 쓰는 액션이 가장 멀리 있다

분석가가 하루에 가장 많이 하는 행동은 무엇일까요? 대개 기간 바꾸기, 필터 조정하기, 특정 지표로 정렬하기입니다. 그런데 많은 도구가 이 핵심 액션을 화면 최상단 우측이나 별도 패널 깊숙한 곳에 숨겨 둡니다. 정작 자주 안 쓰는 설정이 큼지막한 톱니바퀴로 자리를 차지하면서요.

**개선 방향:** 사용 빈도 데이터를 근거로 컨트롤의 위치와 크기를 재배치합니다. 상위 20%의 빈출 액션(파레토 법칙)을 데이터 영역과 가장 가까운 곳, 마우스 동선의 중심에 배치하면 됩니다.

### 2. 표 안의 작은 행 액션

데이터 테이블의 각 행 끝에 달린 ⋯ 메뉴, 3×3px짜리 체크박스, 행 호버 시에만 나타나는 아이콘들. 피츠의 법칙상 최악의 조합입니다. 작고(W↓), 매번 위치가 바뀌며(D 예측 불가), 호버라는 추가 조건까지 붙습니다.

**개선 방향:** 행 전체를 클릭 가능 영역으로 만들어 타깃 크기를 키웁니다. 자주 쓰는 행 액션은 호버에 숨기지 말고 상시 노출하거나, 행 선택 후 화면 상단의 고정된 액션 바로 모으는 패턴이 효과적입니다. 위치가 고정되면 사용자의 근육 기억이 거리를 0에 가깝게 만듭니다.

### 3. 화면 모서리를 안 쓰는 낭비

피츠의 법칙의 유명한 따름정리(corollary)가 있습니다. 화면의 모서리와 가장자리는 무한히 큰 타깃처럼 작동합니다. 마우스를 끝까지 던지면 커서가 화면 밖으로 나가지 못하고 그 지점에 멈추기 때문이죠. 데스크톱 분석 도구에서 좌측 상단 모서리(메뉴), 화면 끝 스크롤바가 누르기 쉬운 이유입니다.

**개선 방향:** 전역적이고 자주 쓰는 기능(전체 검색, 워크스페이스 전환, 저장)은 모서리나 가장자리에 배치해 무한 타깃의 이점을 활용합니다. 단, 데이터 밀도가 높은 화면에서는 가장자리에 다른 요소가 붙어 이 효과가 사라지지 않도록 여백을 확보해야 합니다.

### 4. 위험한 버튼이 너무 쉽다

반대 사례도 있습니다. 전체 삭제, 데이터셋 초기화, 권한 회수 같은 파괴적 액션이 자주 쓰는 버튼 바로 옆에 같은 크기로 놓여 있으면, 피츠의 법칙은 오히려 사고를 가속합니다.

**개선 방향:** 파괴적 액션에는 의도적으로 마찰을 더합니다. 거리를 떨어뜨리고(다른 영역으로 분리), 크기를 줄이고, 확인 단계를 추가합니다. 도허티 임계값과는 반대로, 여기서는 느림이 안전장치가 됩니다.

## 모바일과 터치 환경에서의 변주

태블릿으로 대시보드를 보는 영업·운영 담당자가 늘면서, B2B 도구도 터치를 무시할 수 없게 됐습니다. 터치에서는 손가락이라는 뭉툭한 포인터 때문에 최소 타깃 크기가 훨씬 중요해집니다. 일반적으로 44×44pt(애플)·48×48dp(구글) 이상을 권장합니다.

밀도 높은 데이터 테이블을 터치로 옮길 때는, 모든 것을 다 보여주려 욕심내기보다 핵심 액션만 큰 타깃으로 남기고 나머지는 점진적 공개(progressive disclosure)로 숨기는 전략이 현실적입니다.

- [ ] 터치 환경에서 최소 44pt 타깃을 지키는가?

## 빠름은 곧 신뢰다

분석 도구의 사용자는 도구 자체를 사랑해서 쓰는 것이 아닙니다. 답을 빨리 얻고 싶어서 씁니다. 피츠의 법칙은 그 빠름을 픽셀 단위로 설계하는 언어입니다.

자주 쓰는 것은 크고 가깝게, 위험한 것은 작고 멀게. 이 단순한 원칙 하나만 화면에 일관되게 적용해도, 사용자가 느끼는 마찰은 눈에 띄게 줄어듭니다. 마찰이 줄어든 도구는, 사용자에게 내 시간을 아껴 주는 믿을 만한 동료로 기억됩니다.

내일부터 여러분의 대시보드에서 가장 멀고 가장 작은 버튼 하나를 찾아보세요. 그게 가장 자주 눌리는 버튼이라면, 거기서부터 시작하면 됩니다.
