# 데이터가 없을 때 디자인이 시작된다 — B2B 데이터 분석 서비스를 위한 Empty State 설계 원칙

## 서론 — '비어 있음'은 결함이 아니라 기회다

데이터 분석 대시보드를 처음 열었을 때, 모든 차트가 텅 비어 있는 화면을 마주한 경험이 있을 것이다. 막대그래프 자리에는 회색 격자만 남아 있고, 표 자리에는 헤더만 덩그러니 놓여 있다. 이 순간 사용자는 둘 중 하나를 선택한다. **"내가 뭘 잘못한 건가?"** 하고 의심하거나, **"이 도구가 고장난 건가?"** 하고 떠나거나.

B2B 데이터 분석 서비스에서 Empty State(빈 상태)는 단순한 '데이터 없음' 메시지가 아니다. 이것은 사용자의 첫 인상이자, 가장 자주 마주치는 진입 화면이며, 동시에 가장 자주 디자인 우선순위에서 밀리는 영역이다. 이번 글에서는 빈 상태가 왜 중요한지, 그리고 데이터가 없을 때 디자인이 어떻게 사용자를 다음 행동으로 이끌어야 하는지 이야기해보려 한다.

## 본문

### 1. Empty State의 세 가지 유형 — 같은 '빈 화면'이 아니다

빈 상태는 모두 다른 맥락에서 발생한다. 이를 뭉뚱그려 "데이터가 없습니다"라는 한 줄로 처리하는 것은, 의사가 모든 환자에게 "감기네요"라고 진단하는 것과 같다.

**(1) 최초 사용 빈 상태 (First-Use Empty State)**
- 사용자가 서비스를 처음 켜고 아직 데이터를 연결하지 않은 상태
- 가장 중요한 임무: **"무엇을 해야 하는지"** 명확히 알려주는 것
- 예: "데이터 소스를 연결하면 첫 분석이 시작됩니다 → [데이터 연결하기]"

**(2) 사용자 액션 빈 상태 (User-Triggered Empty State)**
- 필터·검색·정렬 등 사용자의 의도적 조작으로 결과가 0건이 된 상태
- 가장 중요한 임무: **"왜 비었는지"** 설명하고, **"이전 상태로 되돌리는 길"** 을 제공하는 것
- 예: "선택한 기간에는 전환 이벤트가 없습니다. → [필터 초기화] [기간 확장]"

**(3) 시스템 빈 상태 (System Empty State)**
- 데이터 파이프라인 지연, 권한 부족, API 오류 등 시스템 사유로 데이터가 없는 상태
- 가장 중요한 임무: **"기술적 사실"** 과 **"사용자가 할 수 있는 일/할 수 없는 일"** 의 구분
- 예: "데이터 동기화 중 (예상 완료: 약 5분) — 새로고침은 우측 상단 ↻"

같은 '빈 화면'이라도 이 셋은 메시지의 톤, 권장 액션, 시각적 처리가 모두 달라야 한다. **빈 상태의 첫 번째 디자인 결정은 "어떤 유형인지 파악하는 것"** 이다.

### 2. 메시지 위계 — "왜 → 무엇을 → 어떻게"의 3단 구조

빈 상태의 카피는 보통 한두 줄에 모든 정보를 우겨 넣는 함정에 빠지기 쉽다. 다음 위계를 따르면 사용자의 인지 부하를 줄일 수 있다.

**1행 — 상태 선언 (Why is it empty?)**
- 짧고 사실적인 문장. 감정적 표현이나 부정적 어휘는 피한다.
- ❌ "앗! 데이터가 없네요 😢"
- ✅ "선택한 기간에 분석 대상 이벤트가 없습니다"

**2행 — 의미 해석 (What does it mean?)**
- 사용자가 이 상태를 어떻게 해석해야 하는지 보조 설명.
- "지난 30일 동안 이 세그먼트에서는 구매 전환이 발생하지 않았습니다."

**3행 — 다음 행동 (How to move forward?)**
- 1차 액션 1개, 2차 액션 0~1개로 제한.
- [기간을 90일로 확장] · [세그먼트 변경]

3행 구조는 "원인 → 의미 → 행동"의 사고 흐름을 따른다. 사용자가 화면을 보자마자 머릿속으로 자동 실행하는 질문 순서와 일치한다.

### 3. 시각적 처리 — '비어 있음'을 다르게 보여주는 4가지 레벨

빈 상태의 시각적 무게는 **사용 빈도와 사용자의 멘탈 모델**에 따라 달라야 한다. 모든 빈 상태에 일러스트를 깔면 처음에는 따뜻해 보이지만, 자주 마주칠수록 잔소리처럼 느껴진다.

**레벨 1 — 인라인 텍스트 (가장 가벼움)**
- 표 한 행, 작은 카드 내부 등 좁은 공간
- "—" 또는 "데이터 없음" 같은 한 단어 처리
- 사용 빈도: 매우 잦음 (대시보드 내 수십 개 셀)

**레벨 2 — 보조 카피 + 마이크로 액션**
- 위젯 전체가 빈 경우
- "이번 주 전환 0건 · [기간 확장]"

**레벨 3 — 카드형 안내 (제목·설명·CTA)**
- 페이지의 주요 섹션이 빈 경우
- 아이콘 1개 + 3행 구조 카피 + 액션 버튼

**레벨 4 — 풀스크린 온보딩 (가장 무거움)**
- 최초 사용 빈 상태 또는 전체 워크스페이스가 빈 경우
- 일러스트 + 단계별 가이드 + 영상/문서 링크
- 사용 빈도: 평생 1~2회

레벨이 낮을수록 자주 등장하고, 레벨이 높을수록 결정적 순간에 등장한다. **B2B 서비스에서 디자이너가 가장 자주 실수하는 지점은 레벨 2~3에 레벨 4의 무게를 싣는 것** 이다. 일러스트가 매번 화면을 가로막으면, 데이터 분석이라는 본업이 지연된다.

### 4. 안티패턴 — Empty State에서 절대 피해야 할 5가지

**(1) "데이터를 불러올 수 없습니다"만 외치기**
원인도, 해결책도, 다음 행동도 없는 메시지. 사용자에게 좌절감만 남긴다.

**(2) 빈 상태와 로딩 상태를 같은 UI로 표현**
스켈레톤이 영원히 회전하면 사용자는 "정말 로딩 중인지" 알 수 없다. 빈 상태는 **'끝난' 상태**이며, 로딩과 명확히 구분되어야 한다.

**(3) CTA가 두 개 이상**
"새 데이터 연결" · "샘플 데이터 보기" · "도움말 열기" · "관리자에게 문의" — 선택지가 많을수록 사용자는 아무것도 누르지 않는다. 1차 액션은 1개로.

**(4) 사용자 책임 강조**
"필터를 잘못 설정하셨습니다" 같은 책임 전가는 신뢰를 훼손한다. 시스템이 능동적으로 경로를 제안해야 한다.

**(5) 일관성 없는 톤**
한 화면에서는 "데이터가 없어요 🥲", 다른 화면에서는 "Error 404: Resource Not Found". 톤·매너의 진폭이 크면 제품 신뢰도가 떨어진다.

### 5. 데이터 분석 서비스에서만 발생하는 특수 케이스

**(1) "부분적으로 비어 있음" (Partial Empty)**
대시보드의 10개 위젯 중 3개만 데이터가 없는 경우. 전체 페이지 빈 상태로 처리하면 안 된다. 각 위젯 단위로 빈 상태를 디자인하고, 전체적인 '데이터 신뢰도'는 상단 메타 영역에 별도 표시한다.

**(2) "필터링 후 0건 vs 원본 0건"의 구분**
같은 빈 화면이라도 의미가 완전히 다르다.
- 원본 0건: "이 지표는 아직 추적이 시작되지 않았습니다"
- 필터 후 0건: "현재 필터 기준에는 해당 데이터가 없습니다"
이 두 메시지는 서로 다른 액션으로 연결되어야 한다.

**(3) "데이터 권한 부족"의 정중한 처리**
B2B는 권한 기반 데이터 노출이 필수다. 권한 부족 시 "데이터가 없습니다"가 아니라 **"이 데이터를 보려면 [권한명] 권한이 필요합니다 — [관리자에게 요청]"** 으로 표현해야 한다. 보안적으로도, 사용자 경험적으로도 옳다.

## 결론 — 빈 화면은 디자이너가 통제할 수 있는 마지막 영역

데이터 분석 서비스에서 차트의 모양, 색상, 정렬은 분석가가 만든 데이터에 의해 결정된다. 디자이너가 100% 통제할 수 있는 영역은 의외로 좁다. 그러나 **빈 상태만큼은 디자이너의 손에서 시작되어 디자이너의 손에서 끝나는 영역** 이다.

데이터가 없는 순간을 어떻게 다루는지가, 데이터가 있는 순간의 신뢰도까지 결정한다. 사용자가 화면이 비어 있을 때 "이 도구가 나를 안내하고 있다"고 느끼면, 데이터가 채워졌을 때 그 결과를 더 신뢰하게 된다.

오늘 당신의 제품에서 가장 자주 비어 있는 화면 3개를 꼽아보자. 그리고 그 화면이 '실수'처럼 보이는지, '의도된 안내'처럼 보이는지 점검해보자. Empty State는 디자인의 시작이지, 끝이 아니다.
