# B2B 분석 도구에서 사용자를 재방문하게 만드는 트리거 설계법 — 훅 모델의 첫 단계

> 변동 보상이 사용자를 사로잡는 메커니즘이라면, 트리거는 그 사이클을 처음 돌리는 시동 키입니다. B2C는 푸시 알림 한 번이면 끝나지만 B2B 분석 도구의 트리거는 훨씬 정교한 설계가 필요합니다.

## 들어가며

니어 이얼(Nir Eyal)의 『훅(Hooked)』 모델은 트리거 → 행동 → 변동 보상 → 투자, 이 네 단계의 순환으로 사용자 습관이 형성된다고 말합니다. 며칠 전 글에서 다뤘던 변동 보상은 강력하지만 위험한 도구였습니다. 오늘은 그보다 앞 단계, 트리거(Trigger)를 깊게 들여다보려 합니다.

트리거는 사용자가 제품을 떠올리고 행동에 옮기게 만드는 신호입니다. 책에서는 크게 두 가지로 나눕니다.

- **외부 트리거(External Trigger)**: 푸시 알림, 이메일, 슬랙 멘션처럼 제품 바깥에서 들어오는 자극
- **내부 트리거(Internal Trigger)**: 특정 감정이나 상황과 제품 사용이 자동 연결되는 상태 (예: 지루할 때 인스타그램을 켜는 행동)

B2C 앱은 외부 트리거의 향연이지만 B2B 분석 도구의 사용자는 이미 알림 피로(notification fatigue)에 시달리고 있습니다. 무작정 푸시를 쏘면 외면받습니다. 그러면 어떻게 설계해야 할까요?

## 본문

### 1. B2B 분석 도구의 사용자는 이미 떠올리고 있는 경우가 많다

B2C 사용자가 심심해서 앱을 켜는 것과 달리 B2B 분석 도구 사용자는 특정 업무 맥락에서 도구를 찾습니다.

- 월요일 오전 위클리 미팅 준비
- 캠페인 종료 직후 성과 확인
- 임원이 "그 수치 어떻게 됐어?"라고 물었을 때
- 분기 결산 시즌의 KPI 점검

내부 트리거가 이미 작동하고 있는 상황이 많습니다. 우리가 할 일은 새로운 트리거를 심는 것보다 이미 존재하는 트리거를 강화하고 마찰을 줄이는 쪽입니다.

### 2. 외부 트리거 — 알림 피로를 피하는 네 가지 원칙

B2B 환경에서 외부 트리거를 설계할 때 다음 원칙을 지켜야 합니다.

**임계값 기반 알림.** 매일 수치를 알리는 대신 전주 대비 +30% 또는 -30% 이상 변동 같은 임계값을 넘었을 때만 알립니다. 알림이 도착했다는 사실 자체가 지금 봐야 한다는 신호가 됩니다.

**사용자가 직접 설정한 트리거만 발송.** 기본값으로 알림을 켜두면 받는 즉시 OFF로 갑니다. 대신 대시보드 위젯에 "이 지표가 ___% 변동하면 알려주세요" 버튼을 두는 식으로 사용자가 명시적으로 등록한 알림만 보냅니다. 신뢰가 쌓이면 사용자는 점점 더 많은 트리거를 등록합니다.

**메시지에 다음 행동을 명확히 담기.** "전환율이 어제 대비 20% 하락했습니다"보다 "전환율 20% 하락 — 어떤 채널이 영향 줬는지 보기 →"가 훨씬 강력합니다. 트리거의 끝에는 항상 행동(Action)으로 가는 다리가 있어야 합니다.

**채널 다양화.** 업무 시간엔 슬랙, 출근 전엔 이메일 요약, 도구 안에선 배지 — 사용자가 머무는 곳마다 적절한 형태로 트리거를 띄웁니다. 단, 같은 정보를 여러 채널로 중복 발송하지는 않습니다.

### 3. 내부 트리거 — 감정이 아니라 업무 사이클에 박아 넣기

B2C에서 내부 트리거는 주로 감정과 연결됩니다. 외로움, 지루함, 불안. 그런데 B2B에서는 반복되는 업무 사이클이 강력한 내부 트리거입니다.

대표적인 사이클:

- 일일 사이클: 출근 직후 어제 성과 체크
- 주간 사이클: 월요일 위클리 미팅 자료 준비
- 월간 사이클: 월말 마감, 다음 달 예산 계획
- 분기 사이클: 임원 보고, OKR 점검

이 사이클에 우리 도구가 자동으로 떠오르도록 만들려면 사이클의 정점에 우리 도구가 가장 빠른 답을 주는 경험을 반복 제공해야 합니다. 예를 들어 매주 월요일 자동 생성되는 위클리 리포트 템플릿이 한 번의 클릭으로 PPT로 export되면 사용자는 다음 월요일에도 자동으로 도구를 떠올립니다. 월말 마감 시즌이 가까워지면 "지난달 이맘때 평균 마감 소요 시간은 3.5시간이었어요. 미리 시작하시겠어요?" 같은 메시지로 사이클을 자극할 수도 있습니다.

### 4. 트리거가 사라지는 순간 — 권태와 학습된 무시

좋은 트리거도 두 가지 함정에 빠지면 무력해집니다.

**권태(Habituation).** 같은 형태의 알림이 반복되면 뇌가 자동으로 필터링합니다. 매주 같은 시간, 같은 문구의 리포트는 두 달이면 무시됩니다. 해결책은 메시지 형태를 주기적으로 바꾸는 것입니다. 어떤 주는 인사이트 한 줄, 다른 주는 그래프 이미지, 또 다른 주는 동료가 코멘트한 항목을 강조하는 식입니다.

**학습된 무시(Banner Blindness).** 인앱 트리거가 항상 같은 위치, 같은 색으로 노출되면 사용자는 의식적으로도 보지 않습니다. 대시보드 우측 상단의 "새 알림 N건" 배지가 대표적입니다. 이를 피하려면 트리거를 작업 흐름 안에 자연스럽게 녹여야 합니다. 사용자가 특정 캠페인 페이지를 열었을 때 그 캠페인과 관련된 알림만 페이지 상단에 노출하는 방식입니다.

## 결론

B2B 분석 도구의 트리거 설계는 B2C의 푸시 폭격 전략과 정반대 방향으로 갑니다. 적게, 정확하게, 행동으로 이어지도록.

기억해야 할 세 가지:

1. 외부 트리거는 사용자가 등록한 것만, 임계값 기반으로 보냅니다. 신뢰가 곧 트리거의 효력입니다.
2. 내부 트리거는 감정이 아니라 업무 사이클에 연결합니다. 일/주/월/분기 사이클의 정점에 최적의 경험을 배치합니다.
3. 트리거는 권태와 싸워야 합니다. 형태와 위치를 주기적으로 변주하지 않으면 6개월 만에 무력해집니다.

훅 모델의 다음 단계인 행동(Action), 그리고 마지막 단계인 투자(Investment)는 다음 글에서 이어가겠습니다.
