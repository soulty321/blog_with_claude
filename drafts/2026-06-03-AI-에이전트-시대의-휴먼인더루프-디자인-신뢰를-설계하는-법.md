# AI 에이전트 시대의 휴먼-인-더-루프(HITL) 디자인 — 자동화와 통제권 사이에서 신뢰를 설계하는 법

## 들어가며: "맡겨도 되는 일"과 "맡겨선 안 되는 일"의 경계

AI 에이전트가 메일을 분류하고 보고서를 요약하고 데이터셋을 정제하기 시작하면서 디자이너에게 새로운 질문이 떨어졌습니다. **"어디까지 자동화하고, 어디서부터 사용자의 손을 다시 빌릴 것인가?"**

이 경계가 곧 HITL 설계의 핵심입니다. 너무 많은 권한을 에이전트에게 넘기면 사용자는 통제권을 잃고 신뢰를 거둬들입니다. 반대로 확인 단계를 너무 많이 끼워 넣으면 자동화의 본래 가치가 사라집니다. 오늘은 B2B 데이터 분석 서비스를 만드는 디자이너의 관점에서 HITL을 화면 안에 어떻게 녹여낼 수 있는지 살펴보겠습니다.

## 본문

### 1. HITL은 버튼 하나가 아니라 그라데이션이다

HITL을 "AI가 일을 하고 사용자가 OK/Cancel을 누르는 구조"로 단순화하기 쉽지만, 실제로는 자동화 수준의 스펙트럼 위에 여러 의사결정 포인트가 놓여 있습니다.

- **Suggest only (제안만)**: 에이전트가 분석/요약을 보여주고 사용자가 직접 행동을 취한다. 가장 보수적.
- **Recommend & confirm (추천 후 승인)**: 에이전트가 다음 액션 후보를 제시하고 사용자가 한 번의 확인으로 실행한다.
- **Auto-execute with veto (자동 실행 + 거부권)**: 에이전트가 먼저 실행한 뒤 사용자가 일정 시간 안에 되돌릴 수 있다. (Undo 패턴)
- **Full autonomy with audit (완전 자율 + 감사)**: 에이전트가 알아서 실행하고 사용자는 사후 로그/대시보드로만 확인한다.

좋은 HITL 설계는 하나의 제품 안에 네 단계를 적절히 섞어 두는 것입니다. 예컨대 데이터 분석 도구라면 데이터 정제는 Auto + Undo, 이상치 처리는 Recommend & confirm, 리포트 자동 발송은 Suggest only — 위험도에 따라 자동화 수준을 다르게 잡습니다.

### 2. 되돌릴 수 있다는 감각이 신뢰의 8할

사용자가 에이전트에게 권한을 넘길 때 가장 큰 심리적 장벽은 "돌이킬 수 없으면 어쩌지?"라는 두려움입니다. 자동화 비율을 높이려면 그만큼 취소(Undo), 이력(History), 미리보기(Preview) 같은 안전장치를 더 강하게 설계해야 합니다.

체크리스트로 정리하면:

- 모든 자동 실행 액션에는 최소 30초 이상의 명시적 Undo 윈도우가 있다.
- 에이전트가 변경한 데이터는 before / after를 항상 비교할 수 있다.
- 활동 로그(activity log)는 사용자가 검색, 필터, 복원할 수 있는 형태로 제공된다.

세 가지가 갖춰지면 사용자는 "잘못되면 되돌리면 된다"는 안전감 위에서 자동화 수준을 한 단계 더 끌어올리는 데 동의합니다.

### 3. 왜 그렇게 했는지 항상 보여줄 것

LLM 기반 에이전트는 결과의 일관성이 낮습니다. 같은 입력에도 다른 답을 낼 수 있다는 사실을 사용자는 빠르게 알아챕니다. 결과만 보여주면 신뢰가 무너지지만 추론 과정과 근거를 함께 보여주면 신뢰가 유지됩니다.

UI 차원에서 적용할 수 있는 패턴:

- **참조 카드(Source citation)**: 에이전트가 인용한 원본 데이터/문서 링크를 하단에 작은 칩으로 노출.
- **추론 요약(Reasoning summary)**: "최근 7일 매출 추이가 평균 대비 -23%이기 때문에 이 추천을 드립니다" 같은 한 줄 설명을 항상 동반.
- **신뢰도 배지(Confidence indicator)**: 모델이 자체 추정한 확신도를 0~100% 또는 3단계 배지로 표시. 단, 의미가 모호한 숫자(예: 87%)는 오해를 부르므로 차라리 고/중/저 같은 거친 단계가 낫습니다.

### 4. 권한 위임은 한 번에 다가 아니라 점진적으로

신규 사용자에게 처음부터 "에이전트가 알아서 다 처리하겠습니다"라고 말하면 대부분 기능을 꺼버립니다. 점진적 권한 위임 모델을 적용하면 자연스럽게 자동화 수준이 올라갑니다.

권장 흐름:

1. **첫 1주차**: 모든 액션이 Suggest only. 사용자가 직접 실행한 횟수를 기록.
2. **2~4주차**: 사용자가 동일한 패턴으로 5회 이상 승인한 액션에 한해 "다음부터 자동으로 진행할까요?"라고 제안.
3. **4주차 이후**: 사용자가 동의한 액션만 Auto-execute로 승격. 대시보드에서 언제든 다시 Suggest-only로 강등 가능.

사용자가 자신의 손으로 자동화 범위를 키운다는 감각이 핵심입니다. 자동화의 확장 권한이 항상 사용자 쪽에 있어야 합니다.

### 5. 실패를 숨기지 말고 실패의 모양을 디자인할 것

에이전트는 실패합니다. API가 죽거나 모델이 헛소리를 하거나 데이터가 들어오지 않을 때 — 사용자가 보는 화면이 곧 제품의 신뢰입니다. 좋은 HITL 디자인은 실패를 숨기지 않고 실패의 모양을 설계합니다.

- 부분 실패(partial failure)는 별도 상태로 명확히 노출합니다. "30개 중 27개 처리 완료, 3개 실패"처럼 숫자로 보여줍니다.
- 실패한 항목에는 다음 액션이 항상 따라붙어야 합니다. 수동 처리, 다시 시도, 무시 중 고를 수 있게 합니다.
- 모델이 답을 모르면 "추정값입니다" 또는 "직접 확인이 필요합니다" 같은 명시적 경고를 띄웁니다.

침묵하는 에이전트보다 솔직한 에이전트가 훨씬 더 오래 사용됩니다.

## 결론: HITL은 기능이 아니라 관계 설계

휴먼-인-더-루프는 화면 어느 구석에 끼워 넣는 안전장치가 아닙니다. 사용자가 에이전트와 맺는 관계의 곡선 그 자체입니다. 처음에는 보조자로 시작해 점차 동료로, 어떤 영역에서는 대리인으로 — 관계가 자연스럽게 진화하도록 화면을 설계하는 것이 디자이너의 새로운 일입니다.

자동화율을 무리하게 끌어올리려는 PM의 요구와 통제권을 놓지 않으려는 사용자의 욕구 사이에서 다섯 가지를 기억하면 됩니다.

1. 자동화 수준은 그라데이션으로 설계할 것.
2. Undo, History, Preview로 되돌림 감각을 보장할 것.
3. 결과뿐 아니라 추론 근거와 신뢰도를 함께 보여줄 것.
4. 점진적 권한 위임으로 사용자에게 확장권을 돌려줄 것.
5. 실패의 모양까지 디자인할 것.

다섯 가지가 갖춰지면 AI 에이전트는 사용자의 손에서 빼앗는 도구가 아니라 사용자의 손이 닿는 범위를 넓혀주는 도구가 됩니다. 그 경계선을 그리는 사람이 바로 우리, 디자이너입니다.
