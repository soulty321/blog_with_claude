# 사용자는 네비게이션이 아니라 멘탈 모델을 따라온다

> 분석 도구가 점점 무거워지는 진짜 이유는 기능이 많아서가 아니라, 정보가 사용자의 머릿속 구조와 맞지 않게 배치되어 있기 때문이다. 정보 아키텍처(IA)는 단순한 메뉴 구조가 아니라 사용자의 의사결정 경로를 그대로 닮은 지도다.

## 들어가며

B2B 데이터 분석 서비스에서 디자이너로 일하다 보면 한 가지 반복되는 피드백이 있습니다.

> "이 기능, 어디 있었죠?"

심지어 매일 쓰는 사용자에게서도 이 질문이 나옵니다. 처음에는 발견 가능성(Discoverability)의 문제라고 생각했습니다. 그래서 검색을 강화하고 단축키를 추가하고 사이드바를 정리해도 같은 질문은 사라지지 않았습니다.

문제는 메뉴 라벨이나 깊이가 아니었습니다. 정보 구조가 사용자의 멘탈 모델과 어긋나 있었습니다.

UXUI 디자인 교과서가 정보 아키텍처(IA)를 강조하는 이유가 여기에 있습니다. IA는 화면 위의 메뉴 트리가 아닙니다. 사용자가 머릿속에서 정보를 분류하는 방식과 시스템이 정보를 저장하는 방식 사이를 잇는 통역 레이어입니다.

이번 글에서는 B2B 분석 도구에서 정보 아키텍처를 어떻게 설계하는지, 흔히 빠지는 함정 세 가지를 함께 짚어보겠습니다.

## 본문

### 1. IA는 메뉴 구조가 아니라 의사결정 경로다

대부분의 IA 작업은 사이드바에서 시작됩니다. 그런데 사이드바는 결과물이지 출발점이 아닙니다. 출발점은 사용자가 도구를 열고 처음 묻는 질문입니다.

B2B 분석 도구 사용자의 첫 질문은 대개 셋 중 하나입니다.

- "어제와 비교해 무엇이 달라졌는가?"
- "이 지표가 왜 떨어졌는가?"
- "이 결과를 누구에게 어떻게 공유할 것인가?"

이 세 질문은 각각 모니터링, 진단, 공유라는 의사결정 흐름에 대응합니다. 그런데 많은 도구의 사이드바는 기능 이름으로 구성되어 있습니다. "대시보드, 리포트, 세그먼트, 펀널, 알림…" 시스템이 정보를 저장하는 방식이지 사용자가 정보를 찾는 방식이 아닙니다.

좋은 IA는 다음과 같이 다시 묶입니다. 오늘 상태(모니터링) 영역에는 메인 대시보드, 핵심 KPI 카드, 비교 위젯이 놓입니다. 원인 분석(진단) 영역에는 세그먼트 비교, 펀널, 코호트, 드릴다운이 들어갑니다. 공유와 액션 영역에는 리포트, 알림, 슬랙 연동, 익스포트가 자리합니다.

기능을 사용자의 의사결정 단계에 맞게 재배치하면 "어디 있었죠?"라는 질문이 줄어듭니다. 사용자가 이미 머릿속에서 그 단계로 이동했기 때문에 화면도 그 단계의 도구를 보여주면 됩니다.

### 2. 카드 소팅의 함정

IA 설계 워크숍의 표준은 카드 소팅입니다. 사용자에게 기능 카드를 주고 직접 분류하게 하는 방식입니다. B2B 분석 도구에서는 이 방법이 위험할 때가 있습니다.

이유는 두 가지입니다.

첫째, B2B 사용자는 자신의 직무 용어로 분류합니다. 마케터는 "캠페인, 채널, 전환"으로 묶고 데이터 분석가는 "쿼리, 세그먼트, 펀널"로 묶습니다. 두 그룹의 분류는 거의 일치하지 않습니다. 한쪽에 맞추면 다른 한쪽이 길을 잃습니다.

둘째, 사용자는 현재 알고 있는 기능만 분류할 수 있습니다. 새로 추가될 AI 분석 기능, 예측 모델, 자동 인사이트 같은 미래의 기능은 카드 소팅에 등장하지 않습니다. IA가 과거의 사용자 모델에 고정되는 셈입니다.

해결책은 사용자 분류를 출발점으로만 쓰고 의사결정 흐름으로 재조정하는 것입니다.

워크숍에서 나온 분류를 그대로 메뉴로 만들지 말고 "이 분류가 어떤 의사결정 단계에 속하는가?"를 한 번 더 물어야 합니다. 그러면 직무 용어 차이가 흐름 위에서 통합됩니다. 마케터의 "캠페인 성과"와 분석가의 "전환 펀널"은 둘 다 진단 단계에 속한다는 것을 발견하게 됩니다.

### 3. 깊이보다 되돌아가기가 중요하다

IA 가이드의 고전적 원칙은 "메뉴 깊이를 3단계 이하로 유지하라"입니다. B2B 분석 도구에서는 이 원칙이 종종 잘못 적용됩니다. 분석은 선형 흐름이 아니라 사이클이기 때문입니다.

사용자는 대시보드에서 이상치를 발견하고 세그먼트로 들어가서 비교한 뒤 펀널에서 이탈 지점을 찾고 다시 대시보드로 돌아와 다른 지표를 확인합니다. 이 사이클이 매끄럽지 않으면 IA의 깊이가 2단계여도 사용자는 길을 잃습니다.

깊이를 줄이는 것보다 중요한 것은 사이클의 어느 지점에서도 다른 지점으로 빠르게 이동할 수 있게 만드는 일입니다. 구체적으로 세 가지 패턴이 효과적입니다.

첫째, 브레드크럼과 컨텍스트 보존입니다. 깊은 분석 화면에서 상위로 돌아갈 때 필터와 기간 설정이 유지되어야 합니다. 여기서 끊기면 사용자는 처음부터 다시 시작합니다.

둘째, 인접 액션의 즉시 노출입니다. 펀널 화면에서 "이 세그먼트로 보기", "이 기간을 대시보드에 고정" 같은 인접 액션이 같은 화면에 있어야 합니다. 메뉴를 다시 찾아 돌아가지 않게 하기 위함입니다.

셋째, 분석 컨텍스트의 영속화입니다. 마지막으로 본 분석을 기록해두고 도구를 다시 열었을 때 그 컨텍스트로 복귀할 수 있어야 합니다. B2B 사용자는 분석을 며칠에 걸쳐 이어가기 때문입니다.

깊이 1단계의 평면적 IA보다 깊이 3단계여도 사이클이 매끄러운 IA가 더 좋은 사용자 경험을 만듭니다.

### 4. 라벨링은 시스템 용어가 아니라 사용자 어휘로

IA의 마지막 1cm는 라벨링입니다. 가장 자주 실수가 일어나는 지점이기도 합니다.

내부에서는 "코호트 분석"이라고 부르지만 사용자는 "사용자 그룹 비교"라고 검색합니다. 내부에서는 "리텐션 커브"라고 부르지만 사용자는 "재방문율"이라고 찾습니다. 시스템 용어와 사용자 어휘 사이의 거리가 IA의 발견 가능성을 결정합니다.

좋은 라벨링 점검 방법은 단순합니다. 고객 지원 채널의 검색어 로그를 보는 것입니다. 사용자가 "어떻게 ~를 할 수 있나요?"라고 물을 때 사용한 단어가 가장 정확한 사용자 어휘입니다.

라벨링을 사용자 어휘로 맞추면 검색 발견율이 올라가고 온보딩 이탈이 줄어듭니다. 시스템 용어는 툴팁이나 설명 텍스트로 옮기면 충분합니다.

## 결론

좋은 정보 아키텍처는 화면 위에서 보이지 않습니다. 사용자가 길을 잃지 않는다는 사실로만 드러납니다. 사용자의 멘탈 모델과 시스템의 정보 구조가 정확히 맞물려 있다는 신호입니다.

오늘의 핵심을 다시 정리하면 이렇습니다. IA의 출발점은 메뉴 트리가 아니라 사용자의 의사결정 흐름입니다. 카드 소팅은 출발점일 뿐 직무 용어 차이를 의사결정 단계에서 통합해야 합니다. 분석은 사이클이므로 깊이보다 사이클 사이의 이동성이 중요합니다. 라벨링은 시스템 용어가 아니라 사용자 어휘로 맞춥니다.

다음에 분석 도구의 메뉴를 다시 만지게 된다면 "어디 있었죠?"라는 질문이 나오는 지점을 먼저 찾아보세요. 그 지점이 IA가 사용자의 멘탈 모델에서 어긋난 곳입니다. 그곳을 다시 맞추는 작업이 새 기능을 다섯 개 만드는 일보다 가치 있는 경우가 더 많습니다.
