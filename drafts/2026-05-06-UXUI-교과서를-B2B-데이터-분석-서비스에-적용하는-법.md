# UXUI 교과서를 B2B 데이터 분석 서비스에 적용하는 법

안녕하세요. B2B 데이터 분석 서비스를 디자인하다 보면 가끔 의심이 들어요. *"교과서에 나오는 UXUI 원칙들, 결국 모바일 앱 기준 아닌가?"* 16개 컬럼짜리 거대 테이블 앞에선 다 무력해 보이거든요.

결론부터 말씀드리면, **여전히 유효합니다.** 다만 적용하는 무대를 옮겨와야 해요. 오늘은 익숙한 원칙 여섯 개가 B2B 분석 화면에서 어떻게 다르게 작동하는지 정리해볼게요.

---

## 1. 가시성 — 화면이 아니라 '데이터의 상태'를 보여주기

교과서는 "시스템 상태를 항상 보여주라"고 하죠. 모바일에선 로딩 인디케이터 정도면 충분합니다.

근데 분석 도구는 한 층이 더 있어요. **데이터 자체가 어떤 상태인지**를 알려줘야 합니다.

- 이 숫자는 언제 업데이트됐는지?
- 실시간인지, 어제 자정 기준인지?
- 필터가 걸린 결과인지, 전체인지?

화면 한 구석의 작은 "방금 전 업데이트" 표시 하나가, 사용자가 그 데이터를 회의 자료로 캡처할지 말지를 결정하기도 합니다.

## 2. 일치성 — 일상어 대신 도메인 용어 그대로

"폴더", "휴지통" 같은 일상 메타포를 쓰라는 게 교과서의 권장이에요. 그런데 분석 사용자는 오히려 **자기 도메인의 정확한 용어**를 더 원합니다. "세션", "이탈률", "리텐션 코호트"를 풀어 쓰는 게 오히려 신뢰를 깎아요.

다만 같은 용어라도 회사마다 다르게 부르는 경우가 있으니, 우리 서비스의 정의를 명확히 하고 짧은 툴팁으로 보완해주면 좋아요.

## 3. 점진적 공개 — "한 번에 하나" 대신 "한 화면에 충분한 맥락"

모바일은 한 번에 하나만 보여주는 게 미덕이에요. 근데 분석가는 정반대를 원합니다. "캠페인 A의 전환율이 떨어졌다"는 걸 발견한 순간, 세그먼트 차이·시계열·B 캠페인 비교를 동시에 보고 싶어 해요. 클릭 4번을 더 시키면 인사이트의 모멘텀이 꺼져버립니다.

그래서 B2B 점진적 공개는 **'공간'이 아니라 '깊이'**의 문제로 바꿔야 해요.

- **공간**: 요약 + 상세 + 비교를 한 화면에 같이
- **깊이**: 각 정보의 디테일은 hover, 사이드 패널, 드릴다운으로 한 단계 더

## 4. 일관성 — 컴포넌트가 아니라 '데이터 표현'의 일관성

버튼 모양·컬러 일관성은 디자인 시스템이 잡아주죠. 분석 서비스엔 한 층이 더 필요해요. **같은 데이터는 어디서든 같은 모양으로** 보여야 합니다.

- 화면 A는 7일 평균, 화면 B는 30일 평균이 기본값이면 사용자는 혼란에 빠져요
- 같은 "전환율"이 한 곳은 소수점 2자리, 다른 곳은 정수면 같은 지표인지도 헷갈리고요

이건 디자인 토큰뿐 아니라 **메트릭 정의 토큰**까지 합의가 필요한 영역이라, 디자이너 혼자선 못 합니다. PM·데이터 엔지니어와 함께 정리해야 해요.

## 5. 오류 방지 — '실수'가 아니라 '잘못된 해석'을 막기

모바일에선 "삭제하시겠습니까?" 다이얼로그면 충분합니다. 분석 도구에서 진짜 무서운 오류는 다른 데 있어요. **잘못된 해석**이요.

필터가 걸린 줄 모르고 캡처해서 임원에게 공유하면, 그건 기능 오류가 아니라 신뢰 오류가 됩니다.

- 적용된 필터를 컬러 칩으로 상단에 강조
- 차트 제목 옆에 항상 기간 표시 ("2026.04.01 - 04.30")
- 평소보다 10배 차이나는 값엔 자동 ⚠️ 아이콘
- 캡처·PDF 내보내기에 필터 조건 자동 포함

오류 방지의 무대가 모달에서 **메타정보 디자인**으로 옮겨가요.

## 6. 미니멀리즘 — 화면을 비우는 게 아니라 '잡음'을 빼는 것

미니멀리즘이 "화면을 비워라"로 잘못 번역되는 경우가 많아요. 분석 화면을 비우면 사용자에게 "정보가 부족합니다"라고 말하는 셈입니다.

뺄 건 **시각 장식**이에요. 그라디언트, 그림자, 둥근 모서리, 보조 그리드, 장식 아이콘. 채울 건 **정보의 맥락**이고요. "플랫하고 단조롭다"는 평가가 사실 좋은 신호일 수 있습니다. 도구는 멋질 필요 없어요. 신뢰할 수 있고, 빠르고, 정확하면 됩니다.

---

## 정리

| 원칙 | 모바일에서는 | B2B 분석에서는 |
|---|---|---|
| 가시성 | 로딩, 알림 | 데이터 신선도, 적용된 필터 |
| 일치성 | 일상 언어 | 도메인 용어 그대로 |
| 점진적 공개 | 한 번에 하나 | 충분한 맥락 + 단계적 깊이 |
| 일관성 | 컴포넌트 시각 일관성 | 메트릭 정의 일관성 |
| 오류 방지 | 삭제 확인 모달 | 잘못된 해석 방지 메타정보 |
| 미니멀리즘 | 화면 비우기 | 시각 장식만 빼기 |

교과서를 버릴 필요는 없어요. **원칙이 작동하는 무대가 다르다**는 걸 인정하면 됩니다. 매번 화면을 디자인할 때마다 묻게 되는 질문이 있어요. *"이건 예쁜 화면인가, 쓸 수 있는 도구인가?"* — 그 질문이 우리 일을 좋은 일로 만들어주는 것 같습니다.
